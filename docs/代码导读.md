# 代码导读

给**解包后想读懂/改这个插件的人**。配合 `client.js` 里的 `WX-Mxx` 注释一起看：注释里的编号与本文的模块表逐项对应，在编辑器里搜 `WX-M` 就能跳转。

每个编号在文件顶部索引和实现位置各出现一次。例如搜索 `WX-M11`，第一处是索引，下一处是轮次头像计算的实现；要定位具体逻辑也可以直接搜索函数名。

## 0. 先搞清楚它怎么被加载（很重要）

这不是一个能单独跑的 Node 程序：

- **`client.js` 不能 `node client.js` 跑出界面。** 它执行时依赖一个全局的 `window.__ModuleLoader__`，
  由 DSH 的 Web 端注入，`client.js` 只是往里注册一个工厂函数；真正的 `React` 也是通过 DSH 的共享模块表
  `factory(require)` 注入的，不是 `npm i react`。
- **`index.js` 是 Host（主进程/服务端那一半）入口**，由 DSH 启用 bundle 时调用 `apply()`。
  本插件是纯展示层，所以它是空实现——所有能力都在 Client 半边的 `client.js`。
- 加载顺序由 `package.json` 的 `dsh.client`（`platform: web`、`immediately: true`、
  `inject: ['@deepseek-ai/dsh-client-ui-conversation']`）与 `cordis.patch.yml`（把 `dsh-wx-chat`
  插进 web 插件名单）共同声明。
- 想验证改动，正确做法是**让 DSH 重新加载该插件**（插件管理器里重载/刷新页面），而不是直接运行源码。

文件角色：

| 文件 | 作用 |
|---|---|
| `client.js` | 全部功能：样式注入、头像引擎、配置面板、弹窗、会话内组件（WX-M01…WX-M35） |
| `index.js` | Host 半边入口，**刻意留空**；不要为了「顺手」把逻辑搬进去 |
| `package.json` | bundle 清单：`dsh.bundle.patch` + `dsh.client` + `files`（决定分发哪些文件） |
| `cordis.patch.yml` | 把插件行插入宿主插件名单（安装/卸载 bundler 会读它） |
| `locale/zh.json`、`locale/en.json` | 插件在管理器里显示的**名称与描述**（不参与运行逻辑） |
| `icon.svg` | 插件图标 |
| `README.md`、`docs/` | 面向使用者与维护者的文档（本文件即其一） |

## 2. 建议的阅读顺序

1. **WX-M01** 看它是怎么被加载的（`inject`/`apply`/`__test` 三个出口）。
2. **WX-M25** 看装配：注册了哪些 slot、什么时候销毁。这一步决定「组件出现在哪里」。
3. **WX-M02 → WX-M05** 配置从哪来、怎么存、怎么广播。
4. **WX-M11** 头像决策的核心（纯函数、无 DOM，最好懂）。看懂它，头像行为就懂了。
5. **WX-M12** 决策结果怎么落到 DOM 上。
6. **WX-M23** 驱动组件怎么把快照与配置接起来。
7. 再按需看 **WX-M17/WX-M19/WX-M16**（裁剪、上传、弹窗）与 **WX-M22**（面板）。
8. **WX-M24** 最后看样式，对照上面的 data 属性找选择器。

## 3. 数据流

```
                 localStorage["dsh-wx-chat/config-v1"]
                              │ 读 (WX-M04)
                              ▼
                      configSnapshot (WX-M05)  ←── 跨窗 storage 事件
                              │
        ┌─────────────────────┼──────────────────────────┐
        │                     │                          │
   applyConfig (M07)   ConfigPanel (M22)          AvatarDriver (M23)
   写根 CSS 变量         改配置 → commitConfig         │
        │                     │                          │ useChat 快照
        ▼                     ▼                          ▼
   整页 CSS (M24)      configListeners 广播        buildTurnIndex (M11)
                                                       │ turn → {avatar, source}
                                                       ▼
                                              decorateScope (M12) 写行内 --wx-avatar-ai-img
                                                       │
                                                       ▼
                                              行 ::before 画头像 (M24)
```

要点：

- **CSS 不直接读取 JavaScript 配置**：通用外观由 `applyConfig` 写成根元素上的 `--wx-*` 变量与 dataset；每轮动态头像由 `decorateScope` 写到消息行，预览组件还会设置自己的行内变量。
- **头像引擎不猜 DOM 文字**：唯一数据来源是 `useChat` 给的 `ChatSnapshot`；
  DOM 仍用于定位会话区域和消息行、读取 `data-chat-turn` 与点击尺寸；不会从卡片文字中推测工具名或角色状态。
- **状态按 sessionId 隔离**：`infoStore`（M13）与 `roleplay-v1`（M06）都是以会话为键。

## 4. 头像优先级（决策示例）

`buildTurnIndex(snapshot, cfg, roleState)` 为每一轮算出一个 `{ avatar, source, role, running, closed }`。
按下面的顺序读就不容易绕：

1. **本轮有没有未结算的工具调用**（且该轮未终止）→ `running`。
2. **本轮最后一个匹配到的工具头像** → `lastMatched`（按 `anchorSeq` 升序扫，未匹配的不清空它）。
3. **该轮的角色模式** `mode = modeForTurn(roleState, turn)`；`auto` 时用「正文标记累计状态」。
4. 决策：

| 条件 | 头像 | `source` |
|---|---|---|
| 角色开 + 有工具在跑 + 本轮有匹配工具头像 | 该工具头像 | `tool` |
| 角色开 +（工具都跑完 或 本轮没有匹配工具）+ **配了角色图** | 角色头像 | `role` |
| 角色开但**没配角色图** | 走普通规则（下一行） | — |
| 普通 + 工具头像开关开 + 本轮有匹配 | 该工具头像 | `tool` |
| 其余 | 默认头像（`aiAvatar` 或鲸鱼 logo） | `default` |

例子：`cfg.toolAvatars=true`、`toolCategoryAvatars.command` 配了图、`roleAvatar` 配了图、
第 5 轮先跑 `pwsh`（命令类）再跑 `present`（没匹配）：

- 第 5 轮跑 `pwsh` 时：`running=true`，`lastMatched=command图` → 显示 command 图（`tool`）。
- 第 5 轮 `pwsh` 已结束、`present` 仍在运行：`anyRunning` 仍为 true，因为运行状态会统计本轮所有未结束工具，包括没有配置头像的工具；继续显示 command 图（`tool`）。
- 两个工具都结束后：若这轮角色开启且配了角色图，恢复角色图（`role`）；若角色关闭，因为 `lastMatched` 仍保留，继续显示 command 图（`tool`）。
- 第 6 轮没有任何匹配工具：**不继承**第 5 轮的工具头像；角色关闭时用默认头像（`default`），角色开启且配了图时用角色头像（`role`）。

`data-wx-avatar-source` 会写到行上，只作调试与 CSS 钩子，不参与决策。

## 5. 配置流（写一次配置发生了什么）

**默认方案（兼容旧行为）**：

```
面板/弹窗调用 update(patch)
  └─ commitSchemeConfig('default', patch)        (WX-M26 → WX-M05)
       ├─ normalizeConfig()                      补默认值 + 钳制 avatarSize/Roundness/Bg
       ├─ writeConfig()                          写 localStorage[config-v1]，返回 {ok,error}
       ├─ configCache = next                     写失败也保留内存新值（本窗继续生效）
       ├─ applyConfig(document.documentElement, next)   重写根变量
       └─ configListeners 广播                   面板、控件、驱动各自重渲染
```

**具名方案**：同一个入口换成 `commitSchemeConfig(schemeId, patch)`——整库一次原子写
`localStorage[schemes-v1]`（含该方案的那一份 config），**不碰 `config-v1`**。

**会话到底用哪份配置**（2.3 最容易写错的地方）：

```
sessionId ──sessionOverrideId()──▶ 有显式覆盖？ ──有──▶ 用它（source='session'）
                                        │没有
presetId（来自 useSessions 投影）──presetSchemeId()──▶ 有有效绑定？ ──有──▶ 用它（source='preset'）
                                        │没有
                                        └────────────▶ 'default' → config-v1（source='default'）
   ▲
   │ 绑定的方案被删 / 绑定非法 → 该条视为不存在，继续往下回落（只回落，不写回）
   ▼
effectiveConfig(sessionId, presetId) / schemeConfigOf(resolveScheme(...).schemeId)
   ← 驱动、角色设置弹窗、方案选择弹窗、配置面板预览都必须走这条
```

- `presetId` 只从宿主**标准 prop** 读：`useSessions(state => state.byId[sessionId]?.projectionValues?.agentPreset)`，
  仅接受 string；`SessionSnapshot` 上没有 `agentPreset`，不要用 `useSession` 猜。
- 预设的**名单**（id/name）只用来做显示与绑定选项：`bindPresetService(ctx)` 通过
  `ctx.inject(['remote', 'remote.agentPresets'], ...)` 建立可选子 fiber；其回调中的 `attachPresetService(scope)` 才能读取
  `scope.remote.agentPresets.list()`，并订阅 `settings/document-updated(agent-preset-registry)` 与 `connection/reset`。
  服务或事件缺失都**不影响插件其它功能**；名单失败不清绑定，名字回落显示 id，界面给「重试」。
  `ctx.inject` 返回 Fiber，不是可调用的清理函数。服务退出时使在途请求失效、保留仍挂载的 React 订阅；主插件退出才清空整份名单状态。
- 本插件对预设**只读**：不调用 `select / makeDefault / settings.update`，不读预设的组合与提示词。
- **主题**：`system` 不能靠「不写属性」表示。作用域/弹窗宿主上的 system 会被翻译成 `hostThemeNow()`
  的真实值再写上（否则会继承根上**另一个方案**的强制配色），并用 `onHostThemeChange` 跟随宿主切换。
  `hostThemeNow()` **只认**宿主自己的 `data-ds-dark-theme` 标记，不查 `prefers-color-scheme`（宿主可能忽略系统偏好）。
- **合并头像 / 时间戳**同样是「按 scope 的就近变量」：`--wx-merge-vis`（`visibility` 用它）与
  `--wx-ts-display`（`.wx-ts` 的 `display` 用它）在 `:root` 给默认值，由 `[data-wx-merge-avatars='0'|'1']`
  / `[data-wx-timestamps='0'|'1']` 覆盖；作用域上的 dataset 写在自己的元素上，
  **变量在行上解析，所以最近祖先一定赢**，不会出现「根上的 html[…] 选择器压过子 scope」的指定度问题。
  时间戳装饰器的**挂载条件**是「任意一个方案开着时间戳」，具体某个会话显不显示由上面的变量决定。
  同时订阅 `onConfigChange` 与 `onSchemeChange`，只在是否需要装饰器发生变化时启停，避免无关修改重置近似渲染时间。
- **空气泡色也要隔离**：`applyConfig` 把空的 `userBubble`/`aiBubble` 对应变量设为 `initial`，让 `var()` 使用本作用域的主题回落色。直接 `removeProperty` 会继承根上另一方案的自定义色。
- **气泡内宽表格（2.3.1）**：宿主把 Markdown 表格渲染成
  `<div class="_tableScroll_… [md-table-wide 仅 ≥4 列 | _tableFill]"><table>…`；
  `md-table-wide` 的默认样式是 `overflow-x: hidden`（只在 `:hover`/`:focus-visible` 才 `scroll`），
  插件对 user / steering / assistant 三类气泡统一使用 `overflow-x:auto`。
  助手还有 助手正文中的 `.md-table-wide` 跨栏规则，按容器查询宽度计算 `width`、负 `margin-left`、`padding-left`。
  **仅限制 `max-width` 不足以撤销跨栏偏移**：插件同时设 `width:100%; margin-left:0; padding-left:0`，使滚动区域与气泡内容框对齐。
  少列（`_tableFill`）表格继续使用宿主自己的宽度与滚动规则。
  自检要点：加载真实原生 step 的 CSS 和 当前版本助手 root/body 结构；滚动容器的左右边缘必须在气泡内容框内，
  滚到 `scrollWidth - clientWidth` 后最后一列也必须落在可见区域内；页面不能被撑宽。
- **气泡文字色**：`bubbleTextOn` 对 sRGB 通道线性化后计算相对亮度与文字对比度，优先选白字或主题深蓝字；
  两者对比度都不到 4.5 时用黑字，避免中灰、红色背景误判。`applyConfig` 将结果写到
  `--wx-bubble-user-text` / `--wx-bubble-ai-text`；未设自定义底色则写 `initial` 回落主题文字色。
  气泡与外观预览共用这些变量。**不改用户保存的颜色，也不动宿主全局配色。**
- **写操作要绑定目标**：上传/裁剪/CSS 预览这类延迟回调必须记住「按下时的编辑目标」，
  完成时若目标已被切走或方案被删，就丢弃这次结果（`updateFromTask`），绝不写到另一份方案上。
- **补丁合并规则**（`mergeConfigPatch`）：普通字段浅合并，但 `toolCategoryAvatars` 是嵌套对象，
  会**逐键合并**——这样只传「某一类」时不会把其它三类打回默认。新增写入口请沿用这个helper。
- **返回值一定要用**：`ok === false` 时调用方负责把错误显示在**当前最上层**（面板 / 外观预览弹窗 / 角色设置弹窗）。
  校验或目标检查拒绝时 `applied === false`，原设置没变，应提示“未应用”；只有实际更新了缓存但持久化失败时，才提示“本窗已生效、刷新后可能丢失”。GIF 上传提示也要遵守同一规则。
- 同窗不走 `storage` 事件（自己写的不会被自己收到），跨窗才走；
  跨窗要处理三个键：`config-v1`、`roleplay-v1`、`schemes-v1`（`key === null` 表示整体清空）。

## 5.5 气泡内行内代码（2.4 最终形态）

```
宿主：._markdown_1ypvv_5 :not(pre)>code { background: var(--dsw-alias-markdown-inline-code /* 全局 #fafafa，不随主题也不随气泡 */) }
      且 ._markdown_1ypvv_5 { color: var(--dsw-alias-label-primary) } → code 自己不设色，靠继承
插件：WX-M24 里两条 code:not(pre code):not(.md-code-block code) 规则只改三件事：
      底色 transparent、文字 var(--wx-bubble-{ai,user}-text, var(--wx-{ai,user}-text))、
      边框 rgba(127,127,127,.35) 再 color-mix(in srgb, currentColor 25%, transparent)
```

- 早期「派生计算色」方案（`parseCssColor/compositeOn/bestTextOnColor/writeInlineCodeColors` + `--wx-code-*`）
  **已在 2.4 撤销**：跟随主题交给 CSS 变量解析，不需要订阅/重算/缓存。字体、圆角、内边距、边框宽度沿用宿主。
- `:not(pre code)` / `:not(.md-code-block code)` 是关键：只排除父元素 `:not(pre)` 不够，多行代码块里的
  `code` 与高亮 `span` 都必须保持宿主原样。
- 想「跟随主题」不要订阅 `onHostThemeChange`：那会多出一个 body MutationObserver，
  `root-cordis-audit` 的「关闭时间戳后应释放装饰器」不变量会因此失败。

## 5.55 素笺毛玻璃与完整皮肤（2.8.3；WX-M07 + WX-M24 + WX-M31）

**最终形态：由 `applyConfig` 在**每个作用域**完整写入派生变量，CSS 就近继承 —— 不再用祖先属性选择器匹配。**
（早期写成 `[data-wx-glass='1'] …` / `[data-wx-bubble-style='soft'] …` 的祖先选择器会**穿透**：html 上的默认
与内层 session/portal 的相反设置会互相打架。2.5.0 已改成下面的写法，别改回属性匹配。）

```
JS（WX-M07 applyConfig，逐作用域）：
  --wx-glass-{user,ai}-bg      ← glassBaseOf(自定义色)；没自定义写 initial（用主题默认）
  --wx-surface-filter          ← 开：blur(10px) saturate(1.1)；关：none
  --wx-art-*                  ← 每个 scope 的纸色、字色、边框、装饰、位置与间距
  --wx-style-{user,ai}-border  ← var(--wx-art-border)，柔光基础常驻
  --wx-style-{user,ai}-shadow  ← var(--wx-art-shadow)，按纸笺微调柔和外阴影
  --wx-surface-{user,ai}-shadow← 开玻璃时 = inset 高光 .14 + 外阴影
  --wx-surface-{user,ai}-bg    ← 自定义色优先；否则样式纸色（开玻璃时保留 94%，关时原色）
  data-wx-glass / data-wx-bubble-style 仍写（供面板/预览/调试读），但**CSS 不靠它们**。
CSS（WX-M24）：
  气泡与 .wxprev-bubble 直接读上面这些变量：background/filter/box-shadow/border-color。
  @supports (backdrop-filter: blur(1px)) or (-webkit-…) 之外不启用模糊 → 旧内核回退到近不透明底色。
```
- 用户/引导气泡内部的宿主 Markdown 容器也须写入气泡文字色。行内代码由 `--wx-skin-code-bg/ink` 派生：素笺/浅色皮肤为 `.78` 白底与深字，夜间完整皮肤为 `.14` 白底与浅字，避免浅色字落在浅底上；排除 pre 与 .md-code-block，代码高亮保持原色。
- 不对整个气泡用 `opacity`/`filter`；文字色规则不变（100% 不透明）；`--wx-surface-*` 是派生值，**不落盘、不进头像历史**。
- `glassBaseOf` 的 alpha 从 0.90 起，把气泡分别叠到纯黑/纯白端点算最差文字对比，<4.5 就按 0.02 提高（必要时 1.0）。
  **非 hex 的历史颜色（`green`、`rgb(...)` 等）原样保留**（返回 `''` → CSS 回退），不会为了派生而改掉用户颜色。
- **只加在气泡/预览块本身**：`backdrop-filter` 会建立包含块；reasoning、`pre > code`、工具卡、页面一律不加；
  不引入滚动监听 / observer / will-change。
- 强制浅色块必须显式写 `--wx-glass-*-bg-default` 的**浅色**值，否则会继承 body 深色留下的那份。
- 旧 `classic` / `outline` 由 `normalizeBubbleStyle` 合并到 `soft`，校验层仍接受旧值，避免旧文件导入被拒绝。
- 变量都在 `ROOT_STYLE_PROPS`；卸载时随 `clearAppliedConfig` 撤掉（开关/样式 dataset 在 `ROOT_DATASETS`）。
- 面板分区叫「自定义气泡外观」，包括「选择外观」、导入/导出、制作说明与「**毛玻璃**」；`.wxprev-bubble` 的圆角跟随原有圆角滑条。

## 5.6 每轮头像历史（2.4.0，WX-M30）

```
身份（冻结）  avatarIdentityOf(cfg) → userAvatar/userLetter/aiAvatar/roleAvatar/
                                   toolCategoryAvatars/toolRules/toolAvatars/roleMarkerEnabled
外观（不冻结）大小/圆角/头像背景/描边/气泡/主题/时间戳 —— 永远用当前 cfg
```
- **接入点**：`AvatarDriver` 里 `buildTurnIndex(snapshot, cfg, roleState, configFor)`，
  `configFor(turn) = avatarHistory.configFor(sessionId, turn, cfg)`（= 外观取 cfg、身份用历史覆盖）；
  索引里带出 `identity` / `userAvatar` / `userLetter`，装饰时按它写行变量。
- **身份配置按轮冻结；实际发言头像按消息固定（2.9.3）**：未定稿内容仍随工具状态切换，已定稿消息优先使用 `index.messages` 的固定结果；
  `roleMarkerEnabled` / 工具规则 / 角色头像都按该轮保存的那份算，所以改规则只影响下一轮。
- **行变量**：助手行 `--wx-avatar-ai-img`（既有）；用户/引导行新增
  `--wx-avatar-user-img-row` / `--wx-avatar-user-text-row`，CSS 里 `var(行, var(作用域))` 两级回落；
  `resetScope` 三个都要撤。**点击预览必须优先读行变量**，否则会出现"小头像是旧图、点开是新图"。
- **存储**（IndexedDB `dsh-wx-chat/avatar-history`）：
  `assets`（图片及短文字字段的字符串资产） / `snapshots`（身份子集，字符串用资产 key 引用） /
  `turns`（key=`sessionId\0turn` → snapshotId，**首写不可覆盖**）。
  资产与身份快照都以哈希选择桶，再逐项核对内容；碰撞用递增槽位，绝不覆盖旧内容。
  事务将资产、快照与轮次一起提交，`written` 只在提交成功后增加。
- **读取与共享**：`load()` 一次读取三个 store，每份快照只解码一次；内存中的多轮引用同一个
  深复制并冻结的身份对象。`remember()` 等待已有历史读取完成再捕获新轮，防止新配置抢在旧记录前写入。
  持久化失败时保留本窗口的身份，设置页提示一次；坏记录保持原样，不自动删除或覆盖。
- **生命周期**：`apply()` 调用 `activate()`，它可在同一工厂 `dispose()` 后再次启用；
  `generation` 隔离旧异步操作，迟到的连接会关闭，读写和打开数据库均有超时降级。
  驱动在历史就绪前只隐藏头像（`data-wx-avatar-history-pending`），正文照常显示；写完行变量再显示头像。
  `dispose()` 关闭连接、中止本插件事务、清订阅，**不删任何已存历史**。
- `turnKeyOf` 对空 sessionId / 缺失或非整数 turn 返回 `''`（占位节点不得入库，真实数值 0 有效）；
  `smallHash` 是 FNV-1a（**不依赖 crypto.subtle**）；事务里只 await IDB 请求，不 await 网络/加密。

## 6. 上传：分流、取消令牌、裁剪导出
**裁剪交互（2.5.0，WX-M17）**——两套坐标别混，几何函数都是纯函数：

```
舞台坐标：canvas 左上角原点、单位 CSS px。窄屏由 CSS 把 .wxcfg-crop-stage 缩小（min(440px,100%)），
          交互时按 getBoundingClientRect() 现算比例 → CSS 缩放/DPR/resize 都不会跳位；canvas 内部再乘 DPR。
源图坐标：原图像素。导出按 sourceRect 从原图重画。
状态：sel{ x, y, size }（舞台坐标正方形）、view{ scale, tx, ty }（图片在舞台里的缩放与左上角）
纯几何：cropFitView / cropFitSelection / cropClampSelection / cropClampView / cropZoomView / cropSourceRect
        —— cropZoomView 保证"选区屏幕位置与大小不变"（以选区中心为锚），cropClampView 保证"框内不露空"。
交互：pointerdown 用 cornerOf() 判定 角手柄→等比例（锚定对角） / 框内→移框 / 遮罩→移图（框不动）；
      setPointerCapture + pointerup/cancel/lostpointercapture 结束；滚轮用 native non-passive 监听（仅舞台，卸载移除）；
      src 切换用 loadRef 代次丢弃迟到回调；舞台尺寸变化按比例缩放几何。
导出：rect.size（源图边长）→ 位图上限 min(1024, floor(rect.size)) 不上采样、SVG 上限 1024、2MiB 阶梯预算；
      drawImage(img, sx, sy, size, size, 0, 0, out, out) 输出完整方形、不烘焙圆角/alpha。
```

- 导出分辨率与舞台无关：**舞台只是 UI**（440 或更小），导出永远按 `cropSourceRect` 从**原图**重画，
  不要拿舞台 canvas 放大冒充高清（2.3.2 的老坑）。
- **位图**源图小就不上采样（100² PNG → 导出 ≤100²）；**矢量源（SVG）** 不按 `naturalWidth` 当上限，按矢量画到 1024
  （`isVectorImage(img)` 只看已加载 img 的 `src`/`currentSrc`：`data:image/svg+xml` 前缀或 `.svg` 结尾路径；**不探测** content-type、
  不发凭据请求。URL 既不带 `.svg` 后缀又不是 data URL 时按位图处理——这是有意为之的已知局限）。
- PNG data URL 超 `CROP_EXPORT_BUDGET`（≈2MiB）时按 `CROP_EXPORT_LADDER` 逐级降尺寸，**每一步都从原图重画**。
- GIF 不进这条路径（`onGif` 直接保存原 data URL）；只有用户显式「转静态裁剪」才静态化。

```
<input type="file"> change
  └─ 调用方 guard.begin() → token，并立刻显示「正在读取图片…」        (WX-M19)
       └─ readAvatarFile(file, title, handlers, guard, token)
            ├─ FileReader.readAsDataURL
            ├─ onload 后校验 token 是否仍然当前
            ├─ fileLooksLikeGif（二次异步：MIME/扩展名/文件头）
            │    └─ 再校验一次 token（这中间用户可能已取消/重选）
            ├─ GIF   → onGif(dataURL)：直接保存（MIME 规范成 image/gif，字节不动）
            └─ 静态  → onStatic(dataURL)：交给调用方决定是否进裁剪
```

- **取消语义**：`guard.cancel()` 使在飞的读取全部失效并 `abort()` reader。
  调用点：关闭/取消/Esc/点遮罩、卸载组件、切换会话、重新选图、打开「转静态裁剪」。
  **晚到的 onload 不会再弹窗、也不会写配置。**
- **多次上传只最后一次有效**：每次 `begin()` 都会让之前的 token 失效。
- **裁剪导出**（`AvatarCropper.apply`）：按 `cropSourceRect` 从**原图**画到 `size×size` 的方形画布（2.5.0 起舞台只作 UI）→ `toDataURL('image/png')`。
  导出的是**完整方形像素**，不把圆形遮罩或背景色烘焙进图片，原图透明区域仍保持透明；形状交给 CSS，之后可继续调圆角。跨域图片可能让 `toDataURL` 抛错，
  这里必须**如实报错**（错误显示在当时最上层的弹窗里），不能静默失败。

## 7. DOM：伪元素与动态行变量

- 头像**不是**独立元素，而是行的 `::before` 伪元素（`WX-M24`）。所以：
  - 没有可点的节点 → 点击命中用**文档级捕获监听 + 坐标判定**（`attachAvatarClick`），
    并用 `getComputedStyle(row,'::before').width` 读**真实像素**（不能用可能含 `min()` 的变量字符串）。
  - 合并头像/空行会把 `::before` 隐藏，命中判定要跳过（`visibility:hidden` / `display:none`）。
  - 大图预览的圆角/背景/主题**从被点的那一行读**（`::before` 计算样式 + 最近 scope 的 dataset），
    这样同页不同会话不会互相串味。
- **多会话与配置作用域（2.3 重点）**：同一页可能同时显示多个会话，每份外观变量的目标是
  **会话 scope 元素**（最近的 `[data-conversation-content]`），不是 `document.documentElement`。
  - `--wx-avatar-size: var(--wx-avatar-size-base)` 这类**派生变量必须在 scope 里重新声明**：
    它在声明它的元素上就完成了替换，根上算出来的长度会作为定值继承下去，光改 scope 的 base 是不够的。
    所以 `WX-M24` 里这些派生规则同时挂在 `:root` 与 `[data-conversation-content]` 上（窄屏封顶同理）。
  - 强制主题用属性选择器（`[data-wx-theme='dark'|'light']`）写在 scope / 弹窗宿主上；
    `system` 在这些局部宿主上解析成 DSH 的当前主题并随宿主更新，避免继承另一个方案的强制主题；原配置中的 `theme` 仍保存为 `system`。
  - 弹窗 portal 到 `body` 会脱离 scope，所以 `ModalShell` 接收 `appearance` 并把它写到宿主 div 上。
  - 卸载或切方案时要 `clearScopeConfig`，不留旧变量与 dataset。
- 每行的动态头像通过**行内变量**覆盖：`--wx-avatar-ai-img`，
  并写 `data-wx-avatar-source`。`decorateScope` 只碰这些，不动气泡内部节点，因此不会拦截链接/复制/工具控件。
- 行的定位靠 `data-chat-flow-kind`（`user`/`steering`/`assistant-step`/`tool-call`/…）与 `data-chat-turn`。
- **MutationObserver**（`WX-M12`）只对「新增/移除的节点里含 flow 行」或「flow 行的身份属性变化」重排；
  它自己写的 `style` 与 `data-wx-avatar-source` 不在 `attributeFilter` 里，不会自激。
  没有作用域时直接释放观察器。

## 8. 弹窗：portal、焦点、滚动

`ModalShell`（`WX-M16`）：

- 挂载时创建一个 `.wxlayer` 宿主 div 追加到 `document.body`，能用 `react-dom.createPortal` 就 portal 过去
  成功 portal 后可避开设置页祖先的 `overflow`/`transform`。拿不到 portal 时退化成组件内固定层，仍可能受祖先布局影响。
- **层栈**保证 `Escape` 只关最上层；**Tab / Shift+Tab 在弹窗内循环**。
- 打开时记录触发元素与它所在的滚动容器；关闭时**先还焦点**（`preventScroll`），
  **再还原滚动位置**（补一帧 + 一个宏任务，覆盖浏览器滚动锚定的调整），不做多余 setState、不循环。
- 有子层的弹窗（角色设置 → 裁剪）在关闭/切换会话时会把子层一起撤掉。

## 9. 初始化与销毁

`apply(ctx)`（`WX-M25`）做的事：

1. 注入 CSS（`injectCss`，带 `data-plugin` 标记归属）。
2. 写根变量与 dataset（`applyConfig`）。
3. 动态注入可选预设服务；根据所有方案的需求启停时间戳装饰器，并订阅默认配置与方案库变化。
4. 监听 `storage`（跨窗同步）。
5. 注册 slot：`plugins.bundle.config`（配置面板）、`conversation.input.right`
   **三次**——`@local/dsh-wx-chat/driver`（order 5，隐藏标记元素）、
   `@local/dsh-wx-chat/roleplay`（order 10，「角色头像」按钮）、
   `@local/dsh-wx-chat/scheme`（order 12，「头像方案」按钮）。
6. 返回清理函数：解除配置/方案库订阅、通过 `unbindPresetService()` 退出预设子 fiber、反注册 slot 与移除监听，再清理
   `preview.dispose()` → `infoStore.dispose()` →
   `runtime.dispose()`（撤掉行头像覆盖；Driver 的卸载清理另撤掉 scope 配置）→ `clearAppliedConfig(root)` → 移除 `<style>`。
   **只清本插件写的东西**（根变量/dataset/样式/弹层/弹窗宿主/会话 scope 变量）。

`__test` 暴露版本、函数、组件和运行时对象引用，供离线测试夹具调用；**导出本身不会主动调用它们**，其中部分方法在调用时会修改配置、状态或 DOM，并非全是纯函数。这不是面向使用者的稳定 API。
分发包里**不含**历史测试夹具，解包后无需寻找或运行那些开发环境脚本。

## 13. 只预览与显式保存（2.8.5，WX-M32…WX-M34）

`stageAppearance(schemeId, patch)` 只更新允许的 8 个外观字段草稿；`appearanceConfigOf` 合成已保存配置与草稿供局部预览使用。连续事件按帧广播，**不写 localStorage、不修改配置单例、不更新 html 或聊天作用域**。草稿没有自动保存定时器。

- `flushAppearance` 由显式「保存外观」调用，先移除草稿再合并补丁到最新已保存配置。保存失败保留可重试补丁，并沿用 `applied` 协议说明当前窗口是否已应用。提交前拒绝不得污染聊天。`discardAppearance` 取消草稿，不写盘。
- `AppearanceRange` / `AppearanceColor` 使用浏览器原生输入值和局部订阅，立即保留拖动值，避免受控输入在下一预览帧到来前短暂回到旧值。`AppearanceNumber` / `AppearanceLabel` 独立刷新数值，主 `ConfigPanel` 在连续调整时不重渲染。
- 面板只通过 DOM ref 更新自己的样式；`BubbleStyleChoice` 的素笺卡订阅配色和圆角草稿，完整皮肤卡保留自身配色。头像弹窗通过 `useAppearanceCfg` 在弹窗内刷新，`PreviewRow` 按图片源缓存大头像 CSS，避免随大小变化拼接图片串。
- `AvatarDriver` 忽略 pending、cancelled 与提交前拒绝，只处理真正提交后的配置。严格头像身份 memo 与按轮历史冻结规则沿用 2.8.4；不得恢复图片内容采样。
- `commitConfig` / `commitSchemeConfig` 保持同步 API，但不能暗中提交外观草稿。导出/复制取已保存值；编辑方案切换分别保留草稿，删除方案与同源其它窗口更新取消对应草稿。离开配置面板/卸载插件直接取消草稿；pagehide、失焦、松手均无保存动作。
- `ModalShell` 的 `appearance` 变体使用固定宽高、可滚动内容区域与固定头像样例行高，仅随视口上限收敛。其它角色/裁剪/方案弹窗不使用此尺寸规则。
- `configStyleCache` 仍是按 DOM style 保存最后派生值的 WeakMap；`clearAppliedConfig` 同时清缓存。禁止在每次外观刷新时先清空变量，否则缓存失效。

维护验收：连续 userBubble/radius 输入时主面板渲染计数、localStorage 写入、html/聊天样式更新均为零；本地预览和原生输入值仍跟手；Save/Cancel、失败重试、跨方案、普通字段提交与草稿共存、关闭弹窗/面板、固定窗口昼夜及窄屏边界均需验证。


### 头像圆弧轮廓（2.8.6）

`avatarRoundOf` 仍使用 `roundness / 2 + '%'`，100% 对应 50% 半径。头像元素及聊天伪元素显式声明 `corner-shape: round`，避免全局超级椭圆（squircle）把相同半径画成圆角方形；范围仅覆盖插件自己的头像、预览和字母放大层，不重设宿主全局形状。旧浏览器不支持该属性时继续使用原有 border-radius。排查时同时检查宽高、四角半径和 computed corner-shape，不能只看到 50% 就认定已画成正圆。

## 16. 流式与长会话性能（2.9.2）

## 17. 每段发言固定头像（2.9.3）

`buildTurnIndex` 保留数字 turn 索引供用户头像与实时状态使用，另附 `messages: Map<node.key, {avatar, source, capture}>`。`decorateScope` 仅对 response 行按 `data-chat-node-key` 查询消息结果；reasoning 行沿用动态逻辑。观察器监听 node key 变化，兼容同轮内 DOM 复用。

助手节点有可见回复，且 `data.status` 为 settled/interrupted 或轮次已关闭时才能捕获。空白/纯 reasoning/tool-call 块不占位；running→settled、首次可见回复、消息 key 和 step 进入 memo 投影，普通 token 仍复用索引。

首次捕获按发言前的工具和标记结算：有原生 step 时只用更早步骤的工具，避免 interrupted 的 anchor 后移把之后的工具带进来；缺少 step 时按 anchorSeq 回退。已经保存的消息结果优先于之后的工具、配置、角色模式变化。旧版本只有轮次身份，无法恢复未曾记录的每一时刻，只能首次按序补录。

IndexedDB 版本由 1 升为 2，只补建 messages store，旧三表不重写。消息记录保存资产 ID 与来源，不存正文，不复制整份规则。与 assets 同一事务原子首写，跨实例竞争由数据库已有结果胜出；存储失败保留本窗结果并显示原有错误提示。图片共用资源库，最多 16 项的已提交资产引用缓存避免批量补录重复哈希大图；事务提交之前不填该缓存，卸载或连接版本变化时清空。

专项测试覆盖真实 rc.3 节点/注册驱动的连续三段发言、角色标记、重试/中断、DOM 复用、重挂与整页刷新，以及 v1 数据迁移、并发首写、失败回退、卸载中止和大图去重。旧版本程序不能读取 v2 数据库，回退插件版本前需考虑其历史读取能力；不要为回退删除用户数据库。
