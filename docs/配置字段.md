# 配置字段参考

面向**维护者**：把 `client.js` 里真实的默认值、归一化行为、UI 取值范围、存储键结构写清楚。
所有默认值取自 `WX-M02` 的 `DEFAULTS`，取值范围取自 `WX-M22` 配置面板 controls 与
`WX-M03` 的 `normalizeConfig`。

约定：

- **默认值**＝`DEFAULTS` 里的字面值，也是「恢复默认」写回的值。
- **归一化**＝`normalizeConfig()` 在读取/提交时会不会强制收敛。**只有三个字段真的被钳制**：
  `avatarSize`、`avatarRoundness`、`avatarBg`（`toolCategoryAvatars` / `toolRules` 只做结构修复）。
  `radius`、`maxWidth` 等**只有 UI 滑条的 min/max 限制**，手改 localStorage 不会被拦，
  超出范围时就是会按原值渲染。
- **UI 范围**＝配置面板控件的取值域；`—` 表示没有独立控件（由其它控件或代码决定）。

## 1. 存储键

| 键名 | 内容 | 结构 |
|---|---|---|
| `dsh-wx-chat/config-v1` | 整份配置（全局，不分会话） | 扁平对象，见下表字段；缺字段自动补默认值 |
| `dsh-wx-chat/roleplay-v1` | **每会话**的角色模式边界 | `{ "<sessionId>": { "entries": [ { "mode": "on", "fromTurn": 3 } ] } }` |
| `dsh-wx-chat/schemes-v1` | **头像方案库**（2.3 新增）：具名方案 + **预设绑定** + 会话显式覆盖 | `{ "version": 1, "schemes": { "<schemeId>": { "id", "name", "config": {…} } }, "presetBindings": { "<presetId>": "<schemeId>" }, "bindings": { "<sessionId>": "<schemeId>" } }` |

### roleplay-v1 细节

- 外层 key 是**会话 id**（字符串化），所以**每个会话各记各的**，A 会话的模式不会写到 B。
- `entries` 是**按 `fromTurn` 升序**的边界列表；某一轮生效的模式 = `fromTurn <= 该轮` 的**最后一条**记录，没有则 `auto`。
- 同一轮再点一次是**覆盖**该轮那条记录，不是追加。
- `fromTurn` 会被收敛到 `>= 1` 的整数。
- `mode` 只认 `'auto' | 'on' | 'off'`，其它值直接丢弃该条。
- **旧格式迁移**：早期版本这里存的是裸字符串（`"on"`）。读到字符串时会转成
  `{ entries: [], legacyMode: "on" }`，并在**首次得知该会话轮次时**（`AvatarDriver` 发布状态那一步）
  把它钉在「当前未结束轮 / 下一轮」上，**历史消息仍然按 `auto` 处理**。
- 解析失败（JSON 损坏）时整体回落空对象并上报存储错误，不影响其它功能。

可解析的示例（`sessionId` 是占位符）：

```json
{
  "example-session-id": {
    "entries": [
      { "mode": "on", "fromTurn": 3 },
      { "mode": "off", "fromTurn": 8 }
    ]
  }
}
```

含义：第 1–2 轮 `auto`，第 3–7 轮 `on`，第 8 轮起 `off`。

### schemes-v1 细节（2.3 新增）

- **默认方案没有副本**：`DEFAULT_SCHEME_ID = "default"`，它的实时配置就是 `config-v1`。
  这样旧数据零迁移，老用户不需要重新上传头像，也不会在读取时被复制出多份大 GIF。
- 具名方案才把自己的整份 `config` 存在本键里；`id` 形如 `s-<时间36进制>-<随机>`（读入时按同一形状校验，形状不符的条目直接忽略）。
- `presetBindings[presetId] = schemeId`：**智能体预设 → 方案**（默认路径）。只指向存在的具名方案；
  指向 `default` 的预设绑定等同于「没绑定」（跟随默认就是没有绑定）。
- `bindings[sessionId] = schemeId`：**本会话的显式覆盖**（临时例外）。它可以等于 `default`——
  这表示「本会话明确用默认方案」，**与「没有覆盖（跟随预设）」是两回事**，读入时会原样保留。
- **生效顺序（唯一权威解析 `resolveScheme(sessionId, presetId)`）**：
  本会话显式覆盖 > 本会话实际智能体预设的绑定 > 默认方案。
- 两处引用的兜底：缺失、非法、指向已删除方案时按「没有这条引用」处理（只回落，不写回、不伪造成功）。
- 每次修改都是**整个键一次原子写**（不会出现半成品）；上限见下面的「容量规则」。
- 删除具名方案会同时清掉指向它的 `bindings` 与 `presetBindings`，并返回两个计数供界面说明。
- 字典一律用**无原型对象**读写，且只认自有属性：`getScheme('constructor')`、`setSessionScheme(s,'__proto__')`
  这类继承键/危险键既不会变成「有效方案」，也不会污染数据。

### 容量规则与读取修复

| 规则 | 值 | 行为 |
|---|---|---|
| 单个字符串字段（头像 data URL 等） | 3 × 1024² 个字符 | 写入和导入前检查；超限则拒绝且不改动设置 |
| 整个方案库（序列化后字符数） | 6 × 1024² 个字符 | 整库写入前检查；超限则拒绝 |
| 工具名规则条数 | 200 | 配置写入和导入前检查 |
| 具名方案个数 | 50 | 新建、复制和导入前检查 |

- 关键点：**不允许出现「保存成功、刷新后整套消失」**。写路径先校验字段、结构与容量；导入也严格校验。读取已有具名方案时使用 `sanitizeSchemeConfig` 宽容修复：坏字段回默认值，保留其余配置；不是配置对象的条目才丢弃。读取不会为了修复而重写存储。
- 上述字符数依据 JavaScript 字符串长度计算，**不是原始图片文件的字节数**。GIF 转为 data URL 后会变大；浏览器实际存储配额也可能先于插件上限用尽。
- 浏览器配额本身写不下时按写失败处理：「当前窗口已生效，刷新后可能丢失」，不伪造成功、不静默删旧数据。

### 智能体预设（只读）

- 需要宿主服务 `ctx.remote.agentPresets.list()`：成功是 `{ ok: true, value: { presets: [{ id, name, description, broken }] } }`，
  失败是 `{ ok: false, error: { code, message } }`。只取 `id/name`（`broken` 已定义的条目不列入选择，官方类型为可选字符串），
  **不调用 `select` / `makeDefault` / `settings.update`**，不读预设的组合与提示词。
- 会话实际使用的预设 id 来自宿主标准 prop：
  `useSessions(state => state.byId[sessionId]?.projectionValues?.agentPreset)`，仅接受 string。
  `SessionSnapshot` 上没有 `agentPreset` 字段，所以不要从 `useSession` 去猜路径。
- 刷新时机：`ctx.remote.$on('settings/document-updated', ns => ns === 'agent-preset-registry')` 与 `ctx.on('connection/reset', …)`。
  两项更新订阅均可选：名单服务缺失时显示「不可用」，已保存的绑定仍按 ID 生效；仅缺少更新事件时仍可读取名单或手动重试，插件其它功能照常工作。
- 名单只是「显示名称 / 提供绑定选项」用；名单失败**绝不清绑定**。名单恢复后名称自动补上，不需要重发消息。

- **读取兜底**：`schemeConfigOf(不存在的方案)` 不返回 null，而是**回落默认配置**（只读回落）；
  需要区分「不存在」时先调 `getScheme(id)` 判存在。写入路径不受影响（`commitSchemeConfig` 会返回 `ok:false`）。
- **默认方案的变化走另一条通知**：`commitSchemeConfig('default', …)` 写的是 `config-v1`，
  因此只触发 `onConfigChange`，不会触发 `onSchemeChange`。驱动订阅了两者，所以界面照样即时刷新。
- **补丁合并**：`commitConfig` / `commitSchemeConfig` 的补丁是浅合并，但 `toolCategoryAvatars`
  会**逐键合并**（避免只改一类就把其它三类打回默认）。

### 方案里包含 / 不包含什么

- **包含**：`DEFAULTS` 的全部字段（头像、大小、圆角、背景、描边、气泡、气泡圆角、最大宽度、主题、合并头像、时间戳、工具头像与规则、角色头像与自动标记识别）。
- **不包含**：聊天记录、会话 ID、预设绑定、会话绑定、角色模式历史（`auto/on/off` 与 `fromTurn` 边界仍由 `roleplay-v1` 管，**不进入方案**）。

### 导出 / 导入格式

```json
{
  "format": "dsh-wx-chat/scheme",
  "version": 1,
  "name": "示例方案",
  "config": {
    "avatarSize": 48,
    "avatarRoundness": 50,
    "avatarBg": "transparent",
    "theme": "dark"
  }
}
```

- 导出只写上面四个字段（`config` 里也只写允许的配置项）。
- 导入要求 `format` 完全一致、`version === 1`、`config` 为对象且逐字段类型匹配；
  未知字段**忽略**（不报错、也不写进去），坏 JSON / 错版本 / 非法结构一律拒绝且不改动现有数据。
- 导入**总是新建方案**，重名会自动加「 (2)」「 (3)」。

## 2. 配置字段（`dsh-wx-chat/config-v1`）

下表的“归一化”描述基础 `normalizeConfig`。配置写入、具名方案和导入还会经过字段/结构/容量校验；已有具名方案的读取会修复坏字段。不要把基础函数的字符串转换行为理解成“任意错误类型都能保存”。

### 头像图片

| 字段 | 类型 | 默认值 | 归一化 | UI 范围 | 作用 |
|---|---|---|---|---|---|
| `userAvatar` | string | `""` | 不校验 | 文本框 / 上传 | 用户头像：URL 或 data URL；空 = 字母头像 |
| `userLetter` | string | `"我"` | 不校验 | 文本框（最多 2 字） | 字母头像显示的文字 |
| `aiAvatar` | string | `""` | 不校验 | 文本框 / 上传 | 助手头像；空 = 内置官方鲸鱼 logo |
| `toolAvatars` | boolean | `true` | 不校验 | 复选框 | 工具头像总开关；关掉后只区分普通/角色 |
| `toolCategoryAvatars` | object | `{ search: "", read: "", write: "", command: "" }` | 缺键补空串 | 4 行各自「上传/URL/裁剪/清除」 | 按工具**类型**用的头像，空串 = 该类型未配置 |
| `toolRules` | array | `[]` | 过滤非对象项；`name`/`avatar` 转字符串 | 「具体工具名规则」增删 | `[{ "name": "browser_run", "avatar": "..." }]`，**优先于类型** |
| `roleAvatar` | string | `""` | 不校验 | 文本框 / 上传（配置页与角色弹窗都有） | 角色模式用的头像；空 = 角色模式回落到普通规则 |

`toolCategoryAvatars` 的四个 key 就是内置分类：`search`（搜索/浏览）、`read`（读文件）、
`write`（写文件）、`command`（命令/测试）。分类靠工具名的**分段精确命中**关键字，不做子串猜测，
所以请用真实存在的工具名；写规则时填精确工具名（例如 `browser_run`），不要填分类名。

> **裁剪导出（2.5.0）**：配置保存导出的完整方形 PNG data URL。舞台目标边长 440 CSSpx，窄屏自动缩小；
> 舞台仅用于取景，导出按 `cropSourceRect` 从原图绘制。位图尺寸为 `min(1024, floor(源图选区边长))`，最少 1px；
> 小位图不上采样，SVG 可绘制到 1024。超过约 2MiB 的 data URL 预算时逐级从原图降低尺寸重新绘制。
> 圆形/圆角只是预览遮罩，输出保持完整方形及原图透明度；旧版低分辨率头像需重新上传原图裁剪。

> **气泡外观（2.8.1）**：`bubbleGlass`（boolean，默认 `true`）控制毛玻璃，
> `bubbleStyle`（`soft` / `cat` / `lizhi` / `pastoral` / `yuyu` / `yuyu-cat` / `ocean`，默认 `soft`）控制素笺 / 猫猫信笺 / 莉栀小笺 / 田园来信 / 鱼鱼·潮汐来信 / 猫耳鱼鱼 / 澄蓝水波。旧 `classic` / `outline` 读取与导入时正规化为 `soft`。
> 两者参与方案校验、导入导出、复制、预设绑定及弹窗外观指纹；旧方案缺字段使用默认值，非法类型/枚举读修复、写拒绝。
> `applyConfig` 在每个作用域完整写入 `--wx-surface-*` / `--wx-style-*` 派生变量，气泡与预览读取最近的值。
> 这些变量不落盘、不进入头像历史，卸载按 `ROOT_STYLE_PROPS` 清理；`data-wx-glass` / `data-wx-bubble-style` 只作状态标记。
> hex 自定义底色从 90% 不透明度试算，文字对比不足则提高，必要时不透明；无法解析的历史 CSS 颜色保持原样。
> 不支持 `backdrop-filter` 时使用原来的近不透明底色，样式仍可切换。保存的颜色、圆角与宽度不变。

### 头像外观

> **每轮头像历史（2.4.0）不是配置字段**：它存在插件自己的 IndexedDB（数据库 `dsh-wx-chat/avatar-history`，三个 store：
> `assets` 图片资产（按内容去重）/ `snapshots` 头像身份快照（图片用资产 id 引用）/ `turns` 轮次映射（key = `sessionId\0turn`））。
> 轮次记录**首次写入后不再覆盖**；`config-v1` 与 6MiB 方案库都不受影响，导出的方案文件里也不含会话 ID 与头像历史。
> 冻结的只有**头像身份**（`userAvatar/userLetter/aiAvatar/roleAvatar/toolCategoryAvatars/toolRules/toolAvatars/roleMarkerEnabled`），
> 外观字段（大小/圆角/头像背景/描边/气泡/主题/时间戳）永远按当前方案即时生效。

| 字段 | 类型 | 默认值 | 归一化 | UI 范围 | 作用 |
|---|---|---|---|---|---|
| `avatarSize` | number | `36` | **钳制到 24–96 的整数** | 滑条 24–96（另有 36/96 快捷键） | 头像边长 px；同时驱动间距与行最小高度 |
| `avatarRoundness` | number | `100` | **钳制到 0–100 的整数** | 滑条 0–100（另「圆形」= 100） | 连续圆角：border-radius = roundness/2 %，0/50/100 → 直角/圆角方形/圆形 |
| `avatarBg` | string | `""` | **白名单**：`""`/`"transparent"`/`#rgb`/`#rrggbb`，其它回落 `""` | 颜色选择器 +「默认蓝」+「透明」 | 头像背景**纯色**；`""` = 默认蓝 `#4d6bfe`（旧版行为）。不做贴图 |
| `ringColor` | string | `"#4d6bfe"` | 不校验 | 颜色选择器 +「默认蓝」+「无描边」 | 头像外圈描边色；空串 = 无描边 |

派生值（只读，不存盘）：`avatarGapOf()` = `clamp(round(size*0.28), 6, 20)`；
窄窗口（≤480px）实际显示尺寸封顶 32px，见 `WX-M24` 的媒体查询与 `WX-M20` 的说明文案。

### 气泡与行为

| 字段 | 类型 | 默认值 | 归一化 | UI 范围 | 作用 |
|---|---|---|---|---|---|
| `userBubble` | string | `""` | 不校验 | 颜色选择器 | 用户气泡底色；空 = 主题默认 |
| `aiBubble` | string | `""` | 不校验 | 颜色选择器 | 助手气泡底色；空 = 主题默认 |
| （派生）`--wx-bubble-user-text` / `--wx-bubble-ai-text` | CSS 变量 | `initial` | 不落盘 | — | 气泡与预览的文字色：自定义底色时按 sRGB 相对亮度计算对比度，选择白字、主题深蓝字或黑字；否则 `initial` → 回落本主题的 `--wx-user-text` / `--wx-ai-text`。不改保存的底色 |
| `bubbleGlass` | boolean | `true` | 类型校验 | 开关 | 气泡毛玻璃，独立于样式 |
| `bubbleStyle` | string | `"soft"` | 枚举校验，兼容旧值 | 素笺 / 猫猫 / 莉栀 / 田园 / 鱼鱼 / 猫耳鱼鱼 / 澄蓝水波 | 素笺可自定义；六款完整皮肤独立配色与轮廓 |
| `radius` | number | `12` | 不校验（仅 UI 限制） | 滑条 4–20 | 气泡圆角 px |
| `maxWidth` | number | `76` | 不校验（仅 UI 限制） | 滑条 50–90 | 气泡最大宽度 % |
| `showTimestamps` | boolean | `false` | 不校验 | 复选框 | 时间戳装饰；显示的是**本地近似渲染时间** |
| `mergeAvatars` | boolean | `false` | 不校验 | 复选框 | 连续同角色消息只保留一个头像 |
| `theme` | string | `"system"` | 不校验 | 下拉：跟随系统/亮色/暗色 | 强制主题；会写到根元素 `data-wx-theme` |

### 角色模式

| 字段 | 类型 | 默认值 | 归一化 | UI 范围 | 作用 |
|---|---|---|---|---|---|
| `roleAvatar` | string | `""` | 不校验 | 见上 | 角色头像 |
| `roleMarkerEnabled` | boolean | `true` | 不校验 | 复选框「自动标记识别」 | 是否解析助手正文里的角色扮演标记。关掉后 `auto` 不再生效，弹窗会说明已关闭 |

## 3. 空值 / 未配置的含义

| 值 | 含义 |
|---|---|
| 头像字段为 `""` | **未配置**：该入口不生效，回落到上一级规则或默认头像（不是「用透明图」） |
| `avatarBg` 为 `""` | 默认蓝 `#4d6bfe`（与旧版本一致，老配置不需要迁移） |
| `avatarBg` 为 `"transparent"` | 背景真的透明（透明区域露出聊天底色） |
| `ringColor` 为 `""` | 无描边 |
| `userBubble` / `aiBubble` 为 `""` | 用主题默认色 |
| `roleAvatar` 为 `""` | 角色模式下**没有角色图**：改走普通规则（工具头像或默认头像），弹窗会提示「尚未设置角色头像」 |
| `entries` 为空数组 | 该会话所有轮次都是 `auto` |

## 4. 模式与默认状态（容易记错的两点）

- **`mode` 默认是 `auto`**（`DEFAULT_ROLE_MODE`），不是「关闭」。
- **`roleMarkerEnabled` 默认是 `true`**。但 `auto` 只是「允许跟随标记」——
  **在助手回复里还没出现 `on` 标记之前，角色头像不会生效**（初始累计状态是 `off`）。
  想立刻用，手动点「开启」，或让助手在回复里写一行 `[//]: # (wx-roleplay:on)`。
- 「关掉自动标记识别」≠「关闭角色模式」：前者只是不再解析标记，手动「开启/关闭」照样可用。

## 5. 读写、同步与失败

- **同窗**：`commitConfig()` 归一化 → 写盘 → 更新内存快照 → 重写根变量 → 通知订阅者（面板/控件/引擎共用一份快照）。
- **跨窗**：同源且共享同一浏览器数据环境的其它窗口，在 `storage` 事件到达后重新读盘并广播；不同端口、浏览器或浏览器数据环境不会因此同步。`localStorage.clear()`（事件里 `key` 为 `null`）也会触发重新读取默认值。
- **写入失败**（常见：配额不足）：提交返回 `{ ok: false, error }`。配置面板、头像保存和外观弹窗会显示对应错误；内存仍保留新值，**本窗预览不会被旧 localStorage 值覆盖**，但刷新后可能丢失。
- **角色模式按钮的提示边界**：`persistRoleStates()` 也会返回保存结果并广播错误，但当前模式按钮回调没有在角色弹窗里单独展示这次错误；不能只凭按钮高亮判断已经落盘。维护时新增提交入口，应检查返回值并把错误展示给使用者。
- **读取失败**（JSON 损坏 / 存储被禁用）：回落默认值并上报，不抛异常。

## 全局界面偏好（2.6.0，独立于方案）

localStorage 键：`dsh-wx-chat/interface-v1`。结构：`{"whaleSwitches":true}`。
`whaleSwitches` 必须为 boolean，默认 `true`。只控制整个 DSH 的标准开关美化，根元素标记为
`data-wx-whale-switches="1"/"0"`。此字段不加入 `DEFAULTS`、`SCHEME_CONFIG_KEYS`、方案配额、导入/导出或头像历史。
同窗通过监听器更新，跨窗通过 `storage` 事件重新读取；卸载时去掉根标记与插件样式，保留用户偏好供重装使用。
裁剪舞台黑色只是预览背景，不是头像背景配置，也不会进入 PNG 导出。

## 完整皮肤派生值（2.8.1）

`isFullSkin(cfg)` 为 true 时忽略 `userBubble`、`aiBubble`、`radius`、`bubbleGlass` 的视觉效果，
但这四个字段仍保存、导出与回读；切回 `soft` 恢复。不新增持久化字段，昼夜素材也不进入方案 JSON 或头像历史。
`maxWidth` 继续控制消息布局；`avatarRoundness` 是头像圆角，始终独立。
`--wx-skin-*`、`--wx-art-*` 仅为 DOM 派生 CSS 变量，卸载时清理。
预览缩放通过选择卡的 `data-wx-skin-preview="1"`，不进入持久化，不作用于会话正文。
